## HARD-WON MECHANICS (do not re-learn these the hard way)
- Run everything through `uv run --with pyobjc-framework-Quartz` — no system Python has pyobjc.
- **Photos**: per-FILE cycles only. Cmd+A bulk-select hands FB the panel's visual sort
  order (Date Added desc = REVERSED — cost us a full delete/re-add). First cycle:
  Cmd+Shift+D (Desktop) → System Events keystroke folder-alias name → Cmd+Down.
  Then per file: type-ahead `01.jpg` → Cmd+O. The add tile says "Add photo" (singular)
  once ≥1 photo is attached. NEVER send a leading Esc — it closes the panel itself.
  The Go-To sheet (Cmd+Shift+G) is a trap: synthetic Return never registers there.
- **Form fields**: Title/Price are UNLABELED plain inputs (positional 0/1); Description is
  the only `<textarea>`; Category/Condition are `label[role=combobox]`.
  Paste (pbcopy + Cmd+V) works; CGEvent unicode TYPING does not register in FB inputs —
  use System Events `keystroke` for the price digits.
- **Clicks**: two-phase — scrollIntoView, WAIT ≥1.3s (smooth-scroll drift), re-measure,
  verify elementFromPoint hits the right node, then HID-click. FB overlay buttons
  (remove-photo X) need JS `.click()`, not coordinate clicks.
- **Pickers**: JS `.click()` on `div[role=button]` rows is 100% reliable (virtualized list:
  scroll container + retry until the row mounts). Opening pickers is flaky: verified HID
  click on the combobox (elementFromPoint identity) > JS focus + Space (Space sometimes
  just page-scrolls). The category popup overlays the Condition field and ignores Esc —
  toggle it closed by clicking the Category field again.
- **Category labels**: FB shows "Sports & Outdoors" (not "Sporting Goods"), condition
  options have no "Used - Excellent" for most items.
- **Guards** (in fb_common.py): HID watchdog with cross-process attribution
  (/tmp/fb_last_post) — own events don't count as user input; quiet-gate before phases;
  focus gates inside panel flows; aborts the instant real user input lands.
- FB rate-limits listings per window — after the limit clears, space the four posts out
  a bit (publish → verify live → next) to avoid re-triggering it.
