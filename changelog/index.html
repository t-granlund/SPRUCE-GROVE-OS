What actually changed — and how to use it

The month's ~110 commits cluster into eight themes. Each one below is broken down the same way: what it is, how it works under the hood, why it matters to you, and a concrete HTT use case. The marquee features ship with live, hands-on demos — poke them.

① slash commands & interactive UX·v0.0.577 · 0.0.567 · 0.0.469

The terminal learned new verbs

The headline of the month. Three brand-new slash commands — /plan, /undo, and /-search inside /resume — plus a redesigned /set menu, a /theme picker, output-density controls, and typewriter-smooth streaming. These are the surfaces you touch every session.

/plan <goal> — think before it builds

what

A planning-only command. You hand it a goal; it returns a structured plan — objective, numbered steps, risks, a validation checklist — and runs no tools, edits, or shell.

how

It wraps your goal in a "plan-only mode" prompt and routes it through the normal chat pipeline. It's a prompt-level guard, not a hard tool-lock — the model is instructed not to act.

why

Lets you see the agent's intended approach and approve it before any files move — the natural first beat of any unattended run.

watch-out

Because the guard is a prompt, treat /plan as "read-only by convention." For a hard guarantee, pair it with the dangerous-command-guard config.

/plan — routing visualizerinteractive
▸ HTT use case

Before kicking off an overnight script that touches a brand's BigCommerce catalog export, run /plan migrate price rules for Brand X, read the 5-step plan over coffee, and only then let it execute. Plan first, commit second.

/undo — a seatbelt for the agent's edits

what

Reverts the agent's last file change. Aliases /u, /undo_last. Files it created get deleted; files it edited get restored to their prior bytes.

how

A new UndoManager snapshots a file's contents at the top of all five mutators (write, replace, edit, delete, delete-snippet) before the change lands. /undo pops the last snapshot.

why

One keystroke to walk back a wrong edit mid-session — no diff-hunting, no manual restore.

watch-out

The history is an in-memory singleton — it's wiped on every restart. /undo only reverses edits from the current running session, one step per call.

UndoManager — live in-memory stackinteractive
Not a durable rollback. Because the stack lives in RAM, /undo is an interactive safety net, not a substitute for version control. For unattended runs, git is still your real undo.
▸ HTT use case

You're editing a Freshdesk KB template interactively and the agent rewrites the wrong section. /undo, re-prompt, done — instead of fishing the old text out of git stash.

/ in /resume — find a session by what it said

what

Press / inside the /resume session picker to filter your saved sessions by their content — the actual message text — not just by timestamp.

how

A new autosave_search.py builds a lazy, thread-safe content index. The picker pre-warms it on a background thread and short-circuits on metadata (name, date, message count) before loading content.

why

Once you have dozens of sessions, "the one where we debugged the Monday.com webhook" beats scrolling timestamps.

watch-out

Case-insensitive substring match on raw message text — it's recall, not semantic search. Search for terms you actually typed.

/resume content search — try itinteractive
▸ HTT use case

Three weeks ago you worked through a tricky Power BI capacity issue with code_puppy. Type /resume → / → "fabric capacity" and you're back in that exact session, context intact.

② multi-agent orchestration·v0.0.569 · 0.0.x (#377, #486)

Running a swarm, with a kill switch

code_puppy can spin up sub-agents to parallelize work. This month gave that swarm visibility (a live status panel), a clean stop (one Ctrl+C cancels everything), and per-agent model control. If you orchestrate, this is the most consequential bucket.

what

A built-in sub-agent status panel renders a live INVOKE AGENT tree, a single Ctrl+C now cancels the entire swarm (not just the current shell batch), and you can set per-invocation model overrides and tier variants per sub-agent.

how

The panel ships as a built-in plugin reading the agent invocation tree; the cancel path was rewired so one interrupt propagates across every concurrent sub-agent task instead of a single branch.

why

Orchestration without visibility or a stop button is a runaway risk. Now you can see what each agent is doing and halt all of it instantly — and run a cheap model for grunt work, a strong one for synthesis.

watch-out

Per-agent model overrides mean per-agent cost. Map your tiers deliberately or a wide swarm on a premium model adds up fast.

sub-agent swarm — one Ctrl+C cancels allinteractive
▸ HTT use case

Auditing documentation across all 5 brands at once: fan out one sub-agent per brand, watch the tree fill in live, and if one wanders off-scope, a single Ctrl+C stops the whole fleet — no orphaned processes chewing tokens overnight.

③ reliable & durable unattended runs·v0.0.576 · 0.0.572–574 · 0.0.x

Built to survive the night

Your scheduled and long-running jobs are exactly what this bucket protects. Quick-resume after a crash, connection drops that retry instead of faking a crash, concurrent launches that don't corrupt state, and atomic, crash-safe writes. The difference between a job that limps through a blip and one that dies at 2am.

what

--quick-resume / -qr reloads the most recent session for your dir + git branch. Transient VPN/WiFi drops auto-retry. Concurrent launches serialize the DBOS SQLite migration. File & session writes are atomic. A fast Ctrl+C double-tap no longer nukes the REPL.

how

Autosave drops a pointer to the latest session every turn; quick-resume resolves it by a hashed git-root+branch scope. Writes go to a temp file then atomic-rename. A startup lock makes parallel instances take turns through the migration.

why

Unattended automation lives or dies on recovery. A blip used to mean a fake-crash traceback and a lost session; now it's a one-line retry, and restart is one flag back to context.

watch-out

Quick-resume is scoped to git root + branch — switch branches and you'll resume that branch's session, which is usually what you want, occasionally surprising.

blip simulator — old vs. new behaviorinteractive
▸ HTT use case

Your nightly code-puppy-upstream-watch task (this very report) benefits directly: if the office VPN hiccups mid-run, it retries instead of emailing you a scary traceback — and the atomic writes mean a power blip can't leave a half-written session pickle.

what

New providers (Ollama local; Cerebras default-endpoint fix), new models (Opus 4-8, Fable 5 with adaptive thinking), unified selection menus, credential management from the menu, and model-error types distinguished in fallback messages.

how

why

You choose the right brain for each job: a local Ollama model for sensitive franchise data that can't leave the building, a frontier model for hard reasoning, a cheap one for bulk.

watch-out

Because models.json now ships empty, a fresh install needs an explicit /add_model before first use — expected, but don't let it surprise a new teammate.

Your lever for keeping output on-policy

This is the layer that makes code_puppy yours. Project-level plugin discovery, a built-in architecture skill, smarter skill search & activation, an emoji filter, a dangerous-command-guard toggle, hook-engine blocking decisions, and the puppy_kennel memory system. The same "one durable control beats N reminders" principle you run across 200+ locations.

what

Drop plugins in .code_puppy/plugins/ for per-project tooling; skills now match multi-word queries and the agent is told to activate the right one before answering; hooks can block actions via stdout JSON; AGENTS.md is capped at 10k chars.

how

A project-local discovery path loads plugins alongside the built-ins; an enabled_skills module became the single source of truth; the hook engine honors structured stdout payloads to allow/deny a tool call.

why

Governance that travels with the repo. Your voice charter, your guardrails, your franchise conventions become code the agent must load — not reminders it can ignore.

watch-out

Project-level plugins run with the agent's permissions. Treat .code_puppy/plugins/ like any executable in the repo — review before you trust.

⑥ security & safety·v0.0.568 · 0.0.x (#484, #388)

Closing the doors untrusted output can open

Small commits, outsized importance. A terminal clipboard-hijack vector neutralized at the source, a path guard on image loading, a toggle for dangerous-command guards, and atomic writes that can't leave corrupt state. The agent reads untrusted content all day — these harden the blast radius.

what

OSC 52 clipboard hijack from termflow output neutralized so a malicious payload can't silently rewrite your clipboard; load_image guarded against guessed/traversal paths; dangerous-command guards now toggleable.

how

The fix sanitizes the OSC 52 escape sequence at the source before it reaches your terminal emulator — the same "sanitize untrusted output where it enters" instinct, one layer down.

why

When an agent pastes web content or model output into a terminal, escape-sequence injection is a real attack surface. This shuts a known one.

watch-out

The dangerous-command-guard toggle cuts both ways — disabling it removes a safety rail. Keep it on for unattended and shared environments.

▸ HTT use case

For any code_puppy run that ingests external content — scraping a vendor page, reading a customer ticket — the clipboard and path guards mean a poisoned input can't quietly hijack your terminal or read files outside scope.

⑦ cross-platform & output polish·v0.0.574 · 0.0.x (#492, #389, #339)

Same behavior on every machine

A run of fixes that matter most in a mixed Windows/Mac shop: ANSI/CRLF leaks on Windows cleaned up, a Windows first-run Unicode crash fixed, grep made to behave identically across OSes, and output spacing/timing corrected. Fewer "works on my machine" surprises.

what

Stopped an ANSI escape leak from CRLF shell output on Windows; fixed a legacy-codepage UnicodeEncodeError on first run; unified grep pattern handling across OSes; corrected output_level=low spacing and t/s timing.

how

Trailing carriage returns are normalized; the Windows console codepage is handled on startup; grep semantics were aligned so the same pattern matches the same way everywhere.

why

If your team mixes platforms, consistent tool behavior means a script that works on your Mac works on a franchise Windows box without surprises.

watch-out

None material — these are pure correctness fixes. If you'd built workarounds for the old Windows quirks, you can retire them.

▸ HTT use case

When you hand a code_puppy automation to a franchise location running Windows, grep-based checks and shell output now behave exactly as they did on your machine — one less support ticket.

⑧ live steering & input·v0.0.x (Ctrl+T, Ctrl+X)

Talk to a running agent without breaking it

The Ctrl+T steering prompt lets you nudge the agent mid-run. This month killed its input lag, added cursor-aware line editing, stopped arrow keys from cancelling the prompt, and made steer requests inherit the system prompt. Small ergonomics, big day-to-day difference.

what

The mid-run steering prompt (Ctrl+T) gained responsive input and proper left/right cursor editing; arrow keys no longer cancel it; the shell Ctrl+X listener was unified with the canonical key handler; injected steer requests inherit system-prompt instructions.

how

Escape sequences are now parsed instead of treated as cancels, and the steering input shares one key-listener path with the rest of the REPL so behavior is consistent.

why

Steering is how you correct a long run without killing it. When the prompt lags or eats your arrow keys, you lose that control. Now it just works.

watch-out

Steer requests inheriting the system prompt is usually right, but means your governance/voice rules apply to mid-run nudges too — by design.

▸ HTT use case

A long migration is running and you realize it should skip archived brands. Ctrl+T, "skip anything tagged archived," and it adjusts — no restart, no lost progress.
